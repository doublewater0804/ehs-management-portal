EHS 智慧行事曆 R0.4｜跨日活動完整顯示與 ICS 去重

一、R0.4 修正重點
1. 全天、多日且未指定時間，以及已設定起訖時間的跨日行程，均顯示在實際涵蓋的每一天；涵蓋日期可跨月份與年度。
2. EHS 編輯表單的「結束日期」為包含當日在內的日期。例：2026/11/25～11/27 的全天活動，於 25、26、27 三日均顯示。
3. 有起訖時間且結束時間剛好為次日 00:00 時，不將該次日當作活動占用日。
4. 點選跨日事件的任何一天，均編輯原本同一筆行程；不複製、搬移或重寫 Firebase 紀錄。
5. 延續日不會重複顯示第一天的開始時間；無開始時間仍不顯示「未定時間」。
6. ICS 匯出時將同一跨日事件於多日顯示所產生的展開列合併，避免變成多筆 VEVENT；全天 ICS 的 DTEND 維持「不包含結束日」標準，匯入時轉回 EHS 含結束日的日期範圍。
7. 重複活動的每次發生仍是同一個系列，跨日與跨月延續均會顯示，但按任一天編輯會修改整個系列，維持 R0.3 操作規則。
8. 保留 R0.3 分類淺色底、分類標籤、排序；保留 R0.1 的國定假日與月份備註，R0.2 的 ICS 功能。

二、需更新的行事曆檔案（GitHub 儲存庫根目錄的 calendar/）
覆蓋 index.html、app.js、logic.js、ics.js、display.js、README.txt。
不需上傳 style.css、holidays.js、config.js，也不需修改 portal/、backend/、.github/workflows/、Firestore Rules 或其他 EHS 子系統。

三、部署與資料保護
此增量部署包的基準是先前交付的 EHS 智慧行事曆 R0.3（及其 R0.2、R0.1 依賴）。若現有 GitHub 上述檔案自 R0.3 後另有修改，須先比對合併，不能直接覆蓋。
未變更 Firestore Collection/Document 路徑，無資料遷移，不執行任何正式網站／Firebase 寫入。

四、驗收重點
應確認 11/25～11/27 全天事件三天皆顯示，點任一天可編輯同一 ID；跨午夜與 00:00 邊界、跨月與跨年、同分類排序、ICS 匯入／匯出均正常。正式 GitHub Pages、Firebase 讀寫與 Google 日曆實機操作須在部署後驗收。
詳細步驟請見「EHS_智慧行事曆_R0.4_部署說明.txt」。
