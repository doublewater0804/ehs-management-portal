# 空氣污染突發事故緊急應變演練管理系統 R0.2.1

- 操作入口：`air-emergency-drill/index.html`
- EHS 入口分類：環保管理
- 管制：公私場所（麥寮廠、海豐廠）每年至少一次演練；各場所獨立追蹤輪值廠處、預定與實際演練日、實際備查發文日、發文字號、備註、輪值異動理由。
- 發文日期＝演練後向地方環保局正式發函備查日期；期限＝實際演練日＋30個日曆日。
- 基本資料：兩個公私場所由管理員首次按「初始化」才建立；廠處由管理員自行新增（麥寮順序 SM麥寮／PC／ARO1；海豐順序 ARO2／ARO3／PHL／SM3）。自2026年起依序輪值。
- 資料儲存：`esh-v85` Cloud Firestore `(default)`；新系統路徑 `ehs_air_emergency_drill_r0/state/{sites,units,rotations,drills,settings}/...`。
- 登入：沿用 `portal/config.js` 中 Firebase Authentication 設定與已核准的單一管理員帳號；不修改 Firestore Rules。
- Excel：可匯出 `演練管制`、`輪值總覽`、`廠區基本資料`、`廠處基本資料` 工作表。匯入僅讀 `演練管制`；執行前顯示差異與勾選確認，既有更新預設不勾選，無法識別的場所/廠處拒絕匯入。
- PDF：使用瀏覽器列印功能，再選「另存 PDF」，A4 橫式。
- 法規摘要：依2026-11-19查核的全國法規資料庫與環境部主管法規系統，附官方全文連結。系統不自行爬取或更新法規。

## 注意事項

1. 這是完整原始碼 ZIP 內的子系統，不是已在正式 GitHub 上線的證明。
2. **不會在載入頁面時自動建立 Firestore 資料**；由管理員首次點擊初始化按鈕，確認後才寫入兩個場所。
3. 已存的年度演練單據保留當時的演練廠處名稱，基本資料更名不會批次改寫歷史單據；臨時更換廠處需要理由。停用場所不計入未來年度應辦統計，原歷史紀錄仍可檢視。
4. 每個公私場所每年度管理一筆輪值主紀錄，並非支援一個場所同一年無限多筆演練明細。若有追加演練紀錄需額外建立明細模組，應先討論新版需求。
5. 新增加的廠處只有在啟用名單數量達到該場所設定的「預期輪值廠處數」時才正式推算。輪值順序按數字由小到大排列，2026對應順序1；曾儲存的單據不隨基本資料異動而覆蓋。
6. 若預定或實際演練跨年度，應另建當年度紀錄，不將後一年的演練當作前一年合規。
7. 系統對「法規履行狀態」只做資料管制與提醒，不代表主管機關已收件、備查完成或全案合規。

## R0.2 更新（2026-11-19）

- 「年度管理」頁籤及頂部「管理年度」按鈕：明確新增年度、編輯年度備註、進入當年度演練、封存、解除封存、刪除與復原。
- 同一管制年度已有實際演練日期或備查發文日期：禁止刪除，只能封存；封存年度唯讀。
- 無正式演練／發文紀錄的年度刪除使用「邏輯刪除」：僅在 `years/{year}` 標記 `status=deleted`，不刪除 `drills` 與 `rotations` 原始紀錄；可於「查看已刪除的年度」復原。
- R0.1 沒有年度文件的 2026 年與已有 `drills`/`rotations` 年度，會自動辨識為「沿用既有」，無須批次資料遷移。
- 基本資料增加「批次新增廠處」；可一次新增多列，先驗證同場所名稱及啟用輪值順序不可重複，再以一次 Firestore 交易寫入。
- 每個演練廠處新增明確的「編輯／停用或啟用／刪除」。已有演練或輪值歷史引用者禁止永久刪除；未使用者可二次確認後刪除。
- 公私場所包括管理員已建立的「醋酸廠」等自訂場所；本次**不會**刪除、清空或改名。
- 原有年度輪值、30 日備查、Firebase 身分驗證、法規重點、Excel、列印及 EHS 首頁導覽均保留。
- 新資料路徑：`ehs_air_emergency_drill_r0/state/years/{YYYY}`；原資料路徑保留；輪值批次更新防撞文件 `ehs_air_emergency_drill_r0/state/settings/unit-catalog-{siteId}`。

## R0.2.1 整合更新（2026-11-19）

- 頂部僅保留「演練管制總表」「基本資料管理」「法規重點」三個頁籤。「年度管理」及「年度輪值」移至「基本資料管理」頁面內；年度查詢下拉選單只在「演練管制總表」顯示。「統計及設定」獨立頁籤移除，但總表的進度卡片、狀態與逾期提醒仍保留。
- 「基本資料管理」直接按公私場所分組，**每個場所下方同時呈現演練廠處、輪值順序、代碼及管理動作**；新增廠處只需在該場所最後一列輸入並按「新增並儲存」，不用選第二次場所或打開批次新增視窗。
- 公私場所與演練廠處採就地編輯（不另開編輯彈窗），啟用、停用及刪除仍遵循 R0.2 歷史資料保護規則。輪值順序自動接續，亦可手動修改；重複名稱或有效輪值順序衝突時阻止寫入。
- 「演練管制總表」直接使用日期輸入欄位及文字框管理 **預定演練、實際演練、備查期限（自動加30日）、發文日期、發文字號**。每個公私場所獨立按「儲存」，未儲存輸入只作預覽，儲存後同步至原 `drills` 及 `rotations` 文件。
- 每年度輪值、年度新增/封存/邏輯刪除/復原、Excel、PDF、法規摘要、Firebase 權限、EHS 首頁按鈕與既有資料路徑均維持，不做舊資料遷移或初始化重建。
- 移除「統計及設定」的設定介面，不再允許於本頁變更通知提前天數，但保留舊 Firebase 設定紀錄及目前的警示判斷。
- 本次升級只需取代 `air-emergency-drill/index.html`、`app.js`、`style.css`、`README.md`；不可上傳至 GitHub Repository 根目錄覆蓋同名檔案。


## R0.2.2 更新（2026-11-19）

- 「演練管制總表」篩選列新增「年度」選單，與上方「管制年度」雙向同步；保留原有年度管理資料、輪值與演練流程。
- 管制總表下方、說明文字前新增「年度備註」大型多行輸入欄，支援右下角拖曳調整高度、手動儲存，並依年度獨立載入。
- 年度備註與 R0.2 原有 `years/{年度}.note`（年度管理說明，500字）**不同**，新增獨立儲存路徑 `ehs_air_emergency_drill_r0/state/year_notes/{YYYY}`，欄位 `year/content/version/updatedAt/updatedBy/createdBy`，不遷移、不覆蓋既有資料。
- 備註採 Firebase transaction 版本檢查，每份最多 15,000 字；僅在管理員按「儲存備註」後寫入，離線及已封存年度禁止編輯。
- 切換年度發現尚未儲存的日期、發文及年度備註資料時，提供「儲存並切換／放棄變更並切換／取消切換」三種選擇，離頁時另有瀏覽器提示。
- R0.2.2 只修改本子系統 `index.html`、`app.js`、`cloud.js`、`style.css`、`README.md`；不修改 GitHub 根目錄 `index.html`、入口 `portal/`、其他子系統或 Firebase Rules。
- 本機模擬互動／程式測試結果請查閱交付包《驗收紀錄_R0.2.2.md》；實際正式站的 Firebase 讀寫、權限、跨裝置驗收仍須使用者部署後驗證。
