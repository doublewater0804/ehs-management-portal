EHS 智慧行事曆 R0.5｜全系統共用備註與舊月份備註整合

一、R0.5 修改內容
1. 頁面最下方「月份備註」改為「備註」，所有年份與月份共用同一份內容。
2. 切換月份、年度時，備註不切換、不清空；未儲存修改持續保留於畫面。
3. 共用備註必須手動點選「儲存備註」才寫入 Firebase；只有 Firebase 成功後顯示儲存成功。
4. 新增「整合舊月份備註」按鈕：管理員操作後先讀取並預覽所有非空白舊月份備註，確認後才開始整合。
5. 舊月份備註按年月由舊至新排序，格式為【2026年11月】並保留原文、換行。
6. 已經整合的月份將記錄於新文件的 migratedMonthIds，重新執行時不重複加入；同樣完整內容已在共用備註時也避免重複。
7. 整合使用 Firestore transaction，重新檢查舊來源與共用備註，發現並行修改就取消交易；不刪除或修改任何舊月份文件。
8. 限制共用備註 UTF-8 本文約 800 KB，超過時停止操作並提示；不截斷，也不覆蓋舊資料。
9. 沿用 R0.4 跨日行程、R0.3 分類色塊與排序、R0.2 ICS、R0.1 假日底色，以及原本的 Discord 提醒。

二、Firestore 路徑
原有月份備註（保留且不再由新版寫入）：
ehs_smart_calendar_r0/data/monthly_notes/{YYYY-MM}
新版共用備註（新增使用）：
ehs_smart_calendar_r0/data/shared_notes/general

三、重要操作
完成 GitHub 上傳後，以原管理員登入，在頁面下方按「整合舊月份備註」，檢視待整合清單，再按「確認整合至共用備註」。
若沒有任何非空白舊月份備註，或已全部整合，就不會進行重複寫入。
後續直接編輯共用備註並手動儲存；切換任何年度月份都看到同一份備註。

四、部署
只更新 calendar/ 資料夾：app.js、index.html、style.css、README.txt 覆蓋，shared-notes.js 新增。
保留 calendar/ 內其餘檔案及所有 EHS 子系統；不需變更 Firebase Web 設定、Firestore Rules 或 GitHub Actions。
完整步驟請見 EHS_智慧行事曆_R0.5_部署說明.txt。
